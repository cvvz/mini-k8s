# M10d ServiceAccount 与 RBAC 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 引入身份与授权，做法与 Kubernetes 1.24+ 一致：
- 每个命名空间有 default ServiceAccount。
- Pod 自动挂载 bound token，token 由 kubelet 通过 TokenRequest 获取并轮换。
- API Server 认证集群 token（system:masters）与 ServiceAccount JWT，支持 impersonation。
- RBAC（Role、ClusterRole、RoleBinding、ClusterRoleBinding）授权，内置默认策略。
- kk 支持 `create serviceaccount|token|role|clusterrole|rolebinding|clusterrolebinding`、`auth can-i|whoami`、`--as/--as-group`。

**Architecture:**

- **API**：
  - core/v1 ServiceAccount（`sa`），PodSpec 增加 `serviceAccountName`、`serviceAccount`、`automountServiceAccountToken`。
  - 投射卷增加 `serviceAccountToken` 来源。
  - `rbac.authorization.k8s.io/v1` 四种对象：名字允许 `:`（路径段规则），roleRef 不可变，User/Group 主体的 apiGroup 默认为 RBAC 组。
  - 不落库的接口：`serviceaccounts/{name}/token`（TokenRequest）、`selfsubjectaccessreviews`、`selfsubjectreviews`。
- **Token**（`pkg/serviceaccount`）：
  - JWT 的 claims 与 Kubernetes 相同：iss/aud 为 `https://kubernetes.default.svc.cluster.local`，`kubernetes.io.{namespace, serviceaccount, pod}`，sub 为 `system:serviceaccount:ns:name`。
  - Kubernetes 用 RS256 并公开公钥；mini 只有一个 API Server，也只有它校验，因此改用 HS256，32 字节密钥在首次启动时生成并存入 etcd。
  - TokenRequest 默认 1 小时，最短 10 分钟，可绑定 Pod。
- **认证**（`pkg/apiserver/auth.go`）：
  - 集群 token 认证为 `kubernetes-admin`，属于 `system:masters`。
  - JWT 需签名有效、未过期、audience 匹配，且 ServiceAccount（及绑定的 Pod）仍存在、UID 一致。
  - `Impersonate-User`/`Impersonate-Group`：需要 users/groups/serviceaccounts 资源上的 `impersonate` 权限。冒充 SA 时自动补上它所属的组。
- **授权**（`pkg/auth/authorizer/rbac`）：
  - 请求属性的解析方式与 RequestInfoFactory 相同：verb 由方法和是否带名字决定，命名空间、资源、子资源从路径取，discovery 等路径属于非资源请求。
  - `system:masters` 直接放行；其余请求依次匹配 ClusterRoleBinding 与请求命名空间里的 RoleBinding。
  - 拒绝时返回 403，文案与 Kubernetes 相同。
- **默认策略**（`pkg/auth/bootstrappolicy`）：
  - ClusterRole：cluster-admin、admin、edit、view（Kubernetes 的子集）、system:discovery、system:basic-user、system:public-info-viewer。
  - 绑定：cluster-admin 绑定 system:masters；discovery、basic-user 绑定 system:authenticated。
  - 只在缺失时创建。
- **ServiceAccount**：
  - API Server 创建命名空间时同步建 default SA，避免竞态；ServiceAccount 控制器负责补建与重建。
  - **准入**：Pod 的 SA 必须存在，否则返回 403 `error looking up service account ...`。
  - 除非显式关闭，否则注入 `kube-api-access-xxxxx` 投射卷（token 有效期 3607s 加 namespace 文件），挂到所有容器的 `/var/run/secrets/kubernetes.io/serviceaccount`；mirror Pod 不处理。
- **kubelet**（`pkg/kubelet/token`）：按 Pod、SA、audience、有效期缓存 token，有效期过去 80% 后重新请求，投射文件随之更新。
- **未实现**：
  - 不防提权：Kubernetes 禁止授予自己没有的权限，mini 不检查。
  - 没有 kube-root-ca.crt：API 是明文 HTTP。
  - 不支持 aggregated ClusterRole。
  - 控制面组件与插件仍用集群 token。

## AKS 实测（mini-k8s-probe-m10d 命名空间，只建命名空间内对象）

| 项目 | 结果 |
| --- | --- |
| Forbidden | `pods is forbidden: User "system:serviceaccount:ns:robot" cannot list resource "pods" in API group "" in the namespace "ns"`；对象级为 `pods "web" is forbidden: ... cannot get ...`；集群级为 `nodes is forbidden: ... at the cluster scope`；带组的资源为 `deployments.apps is forbidden: ... in API group "apps" ...` |
| create 输出 | `serviceaccount/robot created`、`role.rbac.authorization.k8s.io/pod-reader created`、`rolebinding.rbac.authorization.k8s.io/read-pods created` |
| 列 | sa：`NAME AGE`；role：`NAME CREATED AT`；rolebinding：`NAME ROLE AGE`，wide 加 `USERS GROUPS SERVICEACCOUNTS`（值如 `ns/robot`） |
| describe | role 输出 `PolicyRule` 表（Resources / Non-Resource URLs / Resource Names / Verbs）；rolebinding 输出 Role（Kind/Name）与 Subjects 表 |
| `auth can-i` | 输出 yes/no；"no" 时退出码为 1 |
| `auth whoami` | `ATTRIBUTE VALUE` 表，如 `Username system:serviceaccount:ns:robot`，`Groups [system:serviceaccounts system:serviceaccounts:ns system:authenticated]` |
| 校验 | `rules[0].verbs: Required value: verbs must contain at least one value`、`roleRef.name: Required value`、`roleRef: Invalid value: {"APIGroup":...,"Kind":"Role","Name":"scaler"}: cannot change roleRef` |
| 缺 SA | `pods "ghost" is forbidden: error looking up service account ns/ghost: serviceaccount "ghost" not found` |
| token 卷 | `kube-api-access-gxvxh`，projected 卷的来源为 serviceAccountToken（3607s，token）、configMap kube-root-ca.crt、downwardAPI namespace；挂载为只读；目录为 `..data` 原子写入布局 |
| bound token | claims 包含 `kubernetes.io.{namespace, node, pod, serviceaccount}`，`exp = iat + 3607` |
